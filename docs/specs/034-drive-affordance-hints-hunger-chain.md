# Feature: Drive→Affordance Matching Hints + Hunger Restoration Chain

## Context
- Architecture: [§3 — Agent State Schema](../architecture/03-agent-state-schema.md) (5 drives, 0–100, decay 0.1/s, primary-drive selection), [§4 — Smart Objects & Affordances](../architecture/04-smart-objects.md) (declared `Affordance.effects`), [§6 — PPER Loop](../architecture/06-pper-loop.md) (Perceive/Plan builder dynamic lines)
- Related specs: [018 — Multi-Agent Social](018-multi-agent-social.md) (drive hint pattern, object interactions: conditions/step groups), [024 — Social Tool Invocation Fix](024-social-tool-invocation-fix.md) (imperative hint pattern in perception + plan builders), [032 — Dynamic World Drive Restoration](032-dynamic-world-drive-restoration.md) (bench/stool rest affordances with declared `effects`; the equilibrium validation this spec amends), [019 — Affordance as Tools](019-affordance-as-tools.md) (affordances surfaced to the LLM as tools), [021 — KV-Cache Prompt Optimization](021-kv-cache-prompt-optimization.md) (stable vs dynamic prompt sections)
- Package: `cognition` (perception/plan builders), `examples` (dynamic-world scene + sim state log + docs). **No changes to `shared` or `engine`** — `Affordance.effects` (spec 032) and the builtin furniture handlers already exist; the drive→affordance match is computed in cognition from data cognition already receives.
- Issue: [#130 — Drive→affordance matching hints + hunger restoration chain — agents ignore listed rest affordances, chase phantom remedies](https://github.com/Redna/evol-hive/issues/130)

## Requirements

### Drive→Affordance Matching Hints (cognition)

- **Req 1 — Perception builder hint**: In `packages/cognition/src/pper/perception-builder.ts`, when any drive is below the urgency threshold (`< 40`, half-scale; social already has its own spec-018 hint and is excluded here) AND the current perception contains affordances whose declared `effects` include a **positive** entry for that drive, inject a dynamic line of the form: `Your energy is low (23). Here, you can restore it: garden-bench-1 "sit_outside" (restores energy), garden-bench-1 "relax" (restores energy).` One line per urgent drive, capped at 3 affordance mentions per drive, preserving the LLM's existing tool order.
- **Req 2 — Plan builder hint (imperative)**: In `packages/cognition/src/pper/plan-builder.ts`, the same drive→affordance match (same threshold, same data source) injects an imperative hint following the spec-024 social-hint pattern: `Your energy is low (23). The affordances in your tool list restore it directly (e.g., sit_outside at the Garden Bench). Call such an affordance NOW — do not formulate a search plan.` When the urgent drive is the agent's primary drive and a matching affordance exists, this hint supplements (does not replace) the social directive logic.
- **Req 3 — Data-driven matching only**: The drive→affordance mapping must be computed from the declared `effects: Partial<Record<string, number>>` on each affordance in the current perception — no hardcoded drive→tool table in cognition, no new engine machinery. Drive names must match the `AgentDrives` keys (`energy`, `hunger`, `social`, `comfort`, `curiosity`).
- **Req 4 — Hint suppression (no phantom remedies)**: Hints fire **only** when a matching affordance is actually in the current perception. If an urgent drive has no restoring affordance in perception, no hint is injected for that drive (the LLM's free-form search remains the fallback for genuinely unsatisfiable drives). Hints are emitted into the **dynamic** prompt section only, preserving KV-cache stability (spec 021).

### Hunger Restoration Chain (examples)

- **Req 5 — `harvest` affordance on the planter**: Add `harvest` to `planter-1` in `examples/dynamic-world.ts`, gated by a declarative `AffordanceCondition` (`seeds_planted >= 3`). Its handler in `createDynamicWorldHandlers()` mutates object state (`vegetables +1`, resets `seeds_planted` to 0) and returns `success: true`; declared `effects` include positive `curiosity` (+10) and `comfort` (+5) so it participates in the drive-hint system.
- **Req 6 — `eat` affordance on the planter**: Add `eat` to `planter-1`, gated by `vegetables >= 1` (declarative condition). Its handler consumes one vegetable and applies a **+25 hunger** drive change via `driveChanges`, closing the hunger loop: plant → water → harvest → eat (the object-ecosystem multi-step chain from spec 018's `stepGroup` model, finally exercised end-to-end in the demo).
- **Req 7 — Drive economy documentation**: Update the `dynamic-world.ts` header comment and sim docs to show the complete five-drive economy table (decay AND restoration path for every drive: energy → bench/stool, hunger → eat, comfort → relax/sit_outside/water, curiosity → work loop, social → talk_to/help), mirroring spec 032 Req 4's documentation pattern.

### Five-Drive Observability & Equilibrium (examples)

- **Req 8 — State log prints all five drives**: `logState()` in `examples/dynamic-world-sim.ts` must include hunger (`h=`) and comfort (`co=`) alongside energy, social, and curiosity in every 15s sample (this amends spec 032 AC-5's observational surface).
- **Req 9 — Equilibrium validation, amended spec 032 AC-5**: The 10-min real-LLM run (`USE_REAL_LLM=true SCENE_DURATION_MS=600000`) must show all five drives with restoration bounces and no drive pinned at 0 (hunger previously had no restoration path; energy hints were previously ignored), with thought bubbles referencing listed affordances ("rest at the bench") rather than phantom remedies ("Restore X by find...").

## Acceptance Criteria

- [ ] **AC-1**: With mock cognition, when `energy < 40` and the perception contains `sit_outside`/`relax` (declared `effects: { energy: >0 }`), `PerceptionBuilder` output contains a dynamic line naming the affordance IDs, their object, and the drive restored; `PlanBuilderImpl` output contains the imperative variant. Both are deterministic snapshot tests. (maps to Req 1, Req 2)
- [ ] **AC-2**: No drive→affordance hint is emitted when (a) the drive is ≥ 40, (b) no affordance in perception has a positive `effects` entry for that drive, or (c) the urgent drive is `social` (spec-018/024 hints govern it — no duplicate hint). Hint lines appear only in the dynamic section; the stable-section hash is unchanged for identical room state. (maps to Req 3, Req 4)
- [ ] **AC-3**: `harvest` on `planter-1` fails (returns `success: false`) while `seeds_planted < 3`, and succeeds at `seeds_planted >= 3`, incrementing `vegetables` and resetting `seeds_planted` to 0; `eat` fails while `vegetables < 1` and succeeds with `driveChanges.hunger >= +25`, decrementing `vegetables`. - [ ] **AC-7**: `pnpm -r test && pnpm typecheck && pnpm lint` pass; no changes to `packages/shared` or `packages/engine` source; coffee-shop, morning-routine, and office-day scenes and tests are byte-identical. (maps to Req 1–8 scope constraints)

## Constraints
- **Cognition changes are additive hint lines only** — follow the spec-024 pattern (perception builder: suggestion phrasing; plan builder: imperative phrasing). Do not reorder tools, do not auto-execute affordances, do not add cognition-side drive thresholds beyond the single `< 40` urgency constant (exported from one shared location used by both builders).
- **No `shared`/`engine` package changes.** The matcher consumes `Affordance.effects` already present in `PerceptionResult`; hunger restoration is handler-level (`driveChanges` in the AffordanceResult), matching how spec-032 rest affordances work.
- **Determinism**: all tests except AC-6 pass without LLM calls; the matcher must be a pure function of (drives, perceived affordances) so it is trivially unit-testable.
- **KV-cache safety (spec 021)**: hint lines go in the dynamic section; do not touch stable lines, tool ordering, or system prompt.
- **Performance**: the matcher is O(drives × perceived affordances) per PPER cycle (~5 × ~15 comparisons) — negligible; no caching, no new async work.
- **What NOT to do**: do not duplicate the social-drive hint (spec 018/024 own it); do not change decay rates or `DEFAULT_DRIVES` (spec 019); do not register parallel `harvest`/`eat` handlers that shadow builtin plugins; do not gate `eat` behind object dependencies (`ObjectDependency`) when a declarative `AffordanceCondition` on the same object suffices; do not fix this by re-prompting the LLM in the system prompt — the gap is data-binding (drive → listed affordance), not instruction-following.
