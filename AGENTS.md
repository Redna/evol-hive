# evol-hive

> LLM-driven game engine: autonomous NPCs with embodied cognition in a deterministic TypeScript physics simulation. Local LLMs (Ollama/vLLM/llama.cpp) power a PPER loop (Perceive → Plan → Execute → Reflect) bridged to the engine via Structured Outputs.

## Commands

```bash
pnpm install          # install all workspace deps
pnpm build            # build all packages (tsup)
pnpm dev              # watch mode, all packages
pnpm test             # vitest across all packages
pnpm typecheck        # tsc --noEmit (builds shared first)
pnpm lint             # eslint packages/*/src
pnpm format           # prettier --write
pnpm format:check     # prettier --check
```

## Package structure

Four packages in a pnpm workspace. Dependency direction is strict:

```
shared ← engine
shared ← memory
shared ← cognition
memory ← cognition
```

- `shared` — types, JSON schemas, interfaces. Zero deps. All other packages import from it.
- `engine` — deterministic game loop, physics, spatial/rooms, async LLM routing, smart objects, agents.
- `cognition` — PPER orchestration, LLM client, cognitive tools, guardrails, System-0 classifier.
- `memory` — vector store, weighted retrieval (recency × importance × relevance), reflection.

Never create import cycles. `shared` must not import from any other package. `engine` and `memory` are independent of each other.

## Architecture

The system pairs a deterministic TypeScript engine with non-deterministic LLM cognition. Key concepts:

- **PPER loop** — Perceive (passive awareness), Plan (LLM formulates steps), Execute (engine runs affordance), Reflect (LLM updates state/memory). See `docs/architecture/06-pper-loop.md`.
- **Smart objects** — objects expose discrete affordances; the LLM sees semantics, not implementation. See `docs/architecture/04-smart-objects.md`.
- **System 0 classifier** — fast embedding model prunes affordances before the LLM sees them. See `docs/architecture/05-fast-path-classifier.md`.
- **Structured Outputs** — strict JSON schemas guarantee the LLM response is parseable by the engine. See `docs/architecture/07-structured-outputs.md`.
- **Cognitive guardrails** — affordance masking, contextual forcing, plan validation. See `docs/architecture/10-cognitive-guardrails.md`.
- **Dual-track memory** — short-term injection + long-term vector retrieval with reflection. See `docs/architecture/11-memory-architecture.md`.

Full spec: `docs/architecture/01–11`. ADRs: `docs/adr/`.

## Conventions

- TypeScript strict mode (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`).
- Use `import type` for type-only imports (verbatimModuleSyntax is on).
- Semicolons, single quotes, 2-space indent, trailing commas, 100 char width (see `.prettierrc`).
- Package names: `@evol-hive/<name>`.
- Each package exports from `src/index.ts`. Internal modules use subdirectories with their own `index.ts`.
- Schemas for LLM Structured Outputs live in `packages/shared/src/schemas/llm-schemas.ts`.
- Config files: `config/*.config.ts` (engine, llm, memory).

## Safety

- Ask before adding new dependencies to any package.
- Never modify `pnpm-lock.yaml` by hand — use `pnpm install`.
- Do not edit `dist/` or any `*.d.ts` in `dist/` (generated by tsup).
- **System 1 dream cycle** (spec 035): a run writes outcome samples to `session-logs/` (gitignored) **only if its path opts in** — via `assembleWorld({ system1: { sessionLogDir } })` or `SYSTEM1_SESSION_LOG_DIR`. `examples/visualizer-demo.ts` (real-LLM) and `examples/dynamic-world-sim.ts` opt in and default to `session-logs`; `examples/coffee-shop.ts` uses `SYSTEM1_SESSION_LOG_DIR` when it is set; `USE_REAL_LLM=false` keeps the in-memory sink and writes **nothing**. `scripts/live-sim.mts` prints `evidence=<dir>`, passes the directory to the child, and refuses a real-LLM launch with no sink (spec 067). After sessions run `npx tsx scripts/dream-update.mts session-logs gate-artifact.json`, then relaunch with `SYSTEM1_GATE_ARTIFACT=gate-artifact.json` to serve the trained head.
- Live sims and examples resolve workspace packages (`@evol-hive/engine`, `@evol-hive/cognition`, …) to **built `dist/`**, NOT source — `tsx` only transpiles relative imports. **Always run `pnpm build` (or per-package `tsup`) before launching a live validation run**; a stale dist silently runs old code (cost a full diagnostic arc on 2026-09-06 — see spec 037 Evidence).
- LLM calls are async; the game loop is synchronous. Never block the loop on an LLM response — use the `is_thinking` routing pattern.
- **Launch live sims through `scripts/live-sim.mts`, never the demo directly.** It prints the model it is about to spend on **and the evidence destination** (`evidence=<dir>`, default `session-logs`, `SYSTEM1_SESSION_LOG_DIR` overrides), pauses the run when a **30-minute budget** is spent (`SIM_BUDGET_MINUTES` to change), requires `SIM_UNBOUNDED=1` to run open-ended, and kills the whole process group on Ctrl-C — including a *stopped* child, which needs `SIGCONT` first or it survives as an orphan. It **refuses** a `USE_REAL_LLM=true` launch with no sample sink unless `SIM_NO_EVIDENCE=1` acknowledges it, so a spending run cannot start without leaving evidence. Measured reason: one sim launched directly and left unattended made **47,808 cloud LLM calls over ~16 h** (≈50 calls/minute) and produced no usable observation. Default model `gemma4:31b-cloud`; override with `LLM_MODEL`.
