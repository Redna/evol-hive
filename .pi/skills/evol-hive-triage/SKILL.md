# Triage (evol-hive)

Triage is the front of the ledger: every issue passes through it once, so the
human's "pick the issue" gate sees a legible, verified, agent-ready list — not a
wall of raw reports. Triage is **HITL**: recommend, don't unilaterally decide.

## State machine

Two category roles — `bug` (something is broken) and `enhancement` (new feature
or improvement) — and five states:

- `needs-triage` — not yet evaluated
- `needs-info` — waiting on the reporter
- `ready-for-agent` — fully specified, an AFK leg can take it
- `ready-for-human` — needs a human (judgment, external access, design)
- `wontfix` — will not be actioned

Every triaged issue carries exactly one category and one state. Express them
with the repo's existing labels; if state roles conflict, flag it and ask before
proceeding.

## What needs attention

Present three buckets, oldest first: **unlabeled** (never triaged),
**`needs-triage`**, and **`needs-info` with new reporter activity**. Show counts
and a one-line summary per item; let the human pick.

## Triaging one issue

1. **Gather.** Read the body, comments, labels, author, and any prior triage
   notes (don't re-ask resolved questions). Explore the code using the domain
   glossary and the ADRs in the area.
2. **Redundancy check.** Search for an existing implementation of the requested
   behaviour **by domain concept**, not the request's wording. Report where you
   looked. Found → `wontfix` (already implemented); point to where it lives.
3. **Verify the claim before grilling.** Bug → reproduce from the reporter's
   steps. PR → check it out and run the relevant tests. Report `confirmed` (with
   code path), `failed`, or `insufficient detail` (a strong `needs-info` signal).
4. **Recommend.** State your category + state and reasoning, then wait for
   direction (human gate). Never jump an issue to `ready-for-agent` on your own.
5. **Apply the outcome.**
   - `ready-for-agent` → post an agent brief (below).
   - `ready-for-human` → same brief, plus why it can't be delegated.
   - `needs-info` → "Triage Notes": *established so far* / *what we still need*
     (specific, actionable questions).
   - `wontfix` → close. Rejected enhancement → record it in `.pi/out-of-scope/`
     and link from the closing comment; already-implemented → do **not** record
     it there (that KB is for rejections, not built things).

## Agent brief (what a leg starts from)

```
## What to build
<end-to-end behaviour, user's perspective — not a layer-by-layer list>

## Acceptance criteria
- [ ] criterion

## Blocked by
<issue titles, or "None (can start immediately)">

## Spec
<docs/specs/NNN path if one exists>
```

No gratuitous file paths or line numbers — they go stale.

## Rules

- Every AI triage comment starts with: `> *This was generated by AI during triage.*`
- Refer to issues by **title**, never a bare `#id`.
- Read prior triage notes before re-asking anything.
