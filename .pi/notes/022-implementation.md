# Implementation Notes — Spec 022: Scene Authoring (Declarative)

**PR:** [#96](https://github.com/Redna/evol-hive/pull/96)
**Issue:** [#90](https://github.com/Redna/evol-hive/issues/90)
**Branch:** `feature/022-scene-authoring`
**Date:** 2026-08-26

## Summary

Implemented the full declarative scene authoring system from spec 022: JSON Schema validation, YAML/JSON scene loader with doorway auto-generation, affordance handler plugin system with built-in plugins, and a CLI with three commands (create-scene, validate-scene, run-scene).

## What was built

### 1. JSON Schema (`packages/shared/src/schemas/scene-schema.json`)
- Draft 2020-12 JSON Schema validating the full `SceneDefinition` structure
- Covers Room, SmartObject (with stateRules, compoundActions, dependencies), Affordance (with conditions, stepGroup, stepOrder), and AgentProfile (with all optional persona fields)
- Re-exported as `sceneDefinitionSchema` from `@evol-hive/shared`
- `resolveJsonModule: true` in tsconfig allows direct JSON import; tsup inlines it

### 2. Scene Loader (`packages/engine/src/scene-loader/`)
- `loadSceneFile(filePath)` — reads `.yaml`, `.yml`, `.json`, parses with `js-yaml`, validates with `Ajv2020`, auto-generates doorways, returns `SceneDefinition`
- `SceneValidationError` class with `filePath`, `errors[]` (JSON Pointer paths + messages), and `rawObject` for debugging
- `validateSceneObject(obj)` — standalone validation function
- `autoGenerateDoorways(scene)` — generates `doorway-<roomId>` objects for rooms with `connections` but no existing doorway, matching the `makeDoorway` pattern from `coffee-shop.ts`
- Uses `Ajv2020` (from `ajv/dist/2020.js`) for Draft 2020-12 support

### 3. Handler Plugin System (`packages/engine/src/scene-loader/handler-plugins.ts`)
- `HandlerPlugin` interface: `{ objectType: string, handlers: Record<string, AffordanceHandler>, preconditionCheckers?: Record<string, PreconditionChecker> }`
- Global plugin registry with `registerHandlerPlugin()`, `clearHandlerPlugins()`, `getRegisteredPlugins()`
- `autoRegisterHandlers(core, scene)` — iterates scene objects, finds matching plugins by `type`, registers handlers and precondition checkers (deduplicated)
- `createBuiltinPlugins()` — 5 plugins covering `doorway`, `furniture`, `appliance`, `fixture`, `nature` (handlers refactored from `examples/scene-helpers.ts`)
- Doorway plugin uses `_setSceneManagerForPlugins()` to wire `core.sceneManager` for movement handlers
- Unmatched object types log a warning (per spec constraint)

### 4. CLI (`packages/cli/`)
- New `packages/cli/` package with `bin: { "evol-hive": "./dist/cli.js" }`
- `cli.ts` — entry point with `process.argv` switch (no heavy framework per spec)
- `validate-scene.ts` — loads + validates, prints `✅ Scene is valid` or errors with JSON Pointer paths, exits 0/1
- `create-scene.ts` — interactive wizard using `readline` (TTY mode) or buffered stdin (piped mode for testing)
- `run-scene.ts` — loads scene, creates `EngineCore`, registers built-in plugins + auto-registers handlers, creates PPER orchestrator with mock LLM, assembles game loop, prints agent state snapshots

### 5. Example YAML (`examples/coffee-shop.scene.yaml`)
- Declarative equivalent of `COFFEE_SHOP_SCENE` from `coffee-shop.ts`
- Same 4 rooms, 7 non-doorway objects, 3 agents
- Doorway objects NOT listed — auto-generated by loader
- Passes `validate-scene`

## Key Design Decisions

1. **Ajv2020 for Draft 2020-12**: Standard `Ajv` doesn't support Draft 2020-12; used `ajv/dist/2020.js` (`Ajv2020` class).
2. **Re-export from scene-loader/index.ts**: Both `loadSceneFile` and handler plugin functions are re-exported from `scene-loader/index.ts` so `packages/engine/src/index.ts` only needs one `export *`.
3. **Buffered stdin for create-scene**: `readline` with piped stdin is unreliable; implemented a dual-mode questioner (TTY vs piped) that buffers all stdin lines upfront when non-TTY.
4. **No changes to SceneDefinition**: The YAML is a 1:1 serialization of the existing interface. No new fields, no removals.
5. **Doorway auto-gen in loader, not schema**: Auto-generation happens after validation, before returning `SceneDefinition`. The schema doesn't know about doorways — they're standard `SmartObject` entries.
6. **Built-in plugins**: Handlers from `examples/scene-helpers.ts` are refactored into type-keyed plugins. The example file remains unchanged for backward compat.
